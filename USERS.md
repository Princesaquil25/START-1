# User and Project Definition

This document records the approved Day 1 definition for the career exploration
website. Use it with `AGENTS.md` when making product or content decisions.

## Target users

Adults with prior work experience who want to move away from physically
demanding or unstable jobs and explore administrative or office-based careers.
The initial audience is people who have useful experience but are unsure how
it transfers to office roles.

## Main problem

These users do not know how to connect the skills they already use at work to
administrative or office-based careers, so they are unsure where to begin.

## What the website should help users accomplish

In a short, guided experience, users should be able to:

- identify transferable skills from their existing work experience;
- explore a small set of relevant office-based career pathways; and
- leave with one realistic next step for further exploration or preparation.

## Simple problem statement

> Adults with work experience who want to leave physically demanding or
> unstable jobs need a simple way to understand how their existing skills could
> transfer to administrative and office-based careers, so they can choose a
> realistic next step.

## Scope for the first version

- Start with a small number of administrative and office-based pathways.
- Focus on transferable skills and practical next steps.
- Present pathways as possibilities to explore, not predictions, guarantees,
  or promises of employment.
- Do not build a job board, application tracker, credential verifier, or
  comprehensive labor-market tool in the first version.
- Use approved or project-owner-provided career information when content is
  added.

## Learning sequence

### Day 1 — Define the project

Complete the target-user definition, main problem, website outcome, problem
statement, and scope boundaries. No code is written on Day 1.

### Later days

1. Create a small user flow.
2. Select the minimum approved pathway and transferable-skill data.
3. Design the beginner-friendly interface and interaction behavior.
4. Implement and test the first version.
